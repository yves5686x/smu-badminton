# 开发结构

本项目保持单进程 Web 应用、SQLite 和后台线程，不引入流程引擎或消息队列。
用户名沿用可信使用环境下的操作标识。资源与容量对所有账号相同，因此公共缓存按日期共享；个人预约单独合并。

## 职责与依赖

| 模块 | 职责 |
| --- | --- |
| `routes_booking.py` / `routes_jobs.py` | 请求与响应适配；阻塞业务交给工作线程 |
| `booking_service.py` | 四个预约入口的共同规则、占位、任务启动、学校侧取消 |
| `cas_manager.py` | 单进程线程管理、定时等待、预取与提交；即时预约共用一条执行路径 |
| `booking_store.py` | SQL、原子状态转换、占位归属、历史与过期记录清理 |
| `credentials.py` | 预约所需凭据解析、缓存或重新登录 |
| `booking_api.py` | 学校接口与响应解析；查询失败抛异常，与成功空列表区分 |
| `availability.py` | 公共缓存、共享在途查询、个人预约合并 |

依赖方向为「路由 → 用例服务 → 执行器 / 存储」，执行器调用凭据和学校接口。
可用性走「路由 → 可用性服务 → 学校接口」。路由之间不互相导入，不直接写 SQL。

浏览器不再重复缓存预约结果；普通查询复用服务端公共容量缓存，手动刷新绕过缓存。
页面以任务结果和预约查询结果更新展示，不恢复旧的“处理中”样式作为任务状态。
查询失败时保留上次展示并禁止预约操作，避免将未知容量显示成可预约。

## 状态与流程

状态用于查询和展示；流程用普通函数表达等待、登录、提交和收尾。
没有为每个步骤建立状态节点。保留 `scheduled/running/done/failed/skipped/cancelled`。

- 冲突检查与占位插入使用一个 SQLite 写事务，同用户同日跨场地并发也不能绕过检查。
- 先保存任务，再启动线程；保存失败不得产生不可追踪的后台任务。
- 任务保存 `local_booking_id`，失败、跳过或取消时只释放自己的记录。
- 状态转换以条件更新完成；终态不可覆盖，状态与占位释放在同一事务提交。
- 活跃任务的停止操作先设置取消事件，由执行器收尾。已发出的请求不能撤回，须等结果返回。
- 若请求在取消期间成功，记录成功，保留占位；随后可通过取消预约接口撤销学校侧预约。
- 取消接口返回 `pending` 表示执行尚未结束，前端提示等待，稍后确认并按需再次取消。
- 已成功预约的本地记录，在学校侧确认取消成功或确认不存在后删除；查询失败时保留。

即时同步与后台路径共用提交逻辑。定时抢票由主线程完成准备、等待和到点资源解析，提交线程仅执行一次提交，最多两次并发。
令牌有效期不足时强制重新登录，并重建绑定新令牌的验证码；重新登录失败才结束任务。
普通预热在 T-35 秒停止启动新解码；临近开抢创建任务或重新登录后，限次补准备验证码。
需要验证码但未准备成功时不裸提交。到点资源解析共享 4 秒查询预算，不嵌套重试或隐式重登。
该预算用于查询准入、请求超时和丢弃超时结果，并非强制终止底层网络调用的硬实时保证。
粗等待使用可中断的本地时钟等待，在预取窗口校时，避免外部校时故障使等待永远无法推进。

## 数据库升级与运行边界

启动建表时会幂等增加 `scheduled_jobs.local_booking_id`，不会删除历史数据。
旧任务没有可信的占位归属，升级时保持该字段为空，不猜测并删除可能属于其他任务的记录。
这些旧占位可在确认学校侧预约后通过取消接口释放，或在场次结束后由过期清理释放。
新任务的占位归属在重启后保留。

执行器按单进程设计，不支持多个 worker 共享数据库抢占任务。未引入分布式租约。
预约提交超时后的学校侧结果仍可能不确定；当前没有自动对账流程，需通过学校侧查询确认。
中断时处于提交阶段的任务恢复也没有完整对账，正式抢票期间应避免重启进程。
查询封装不再隐式刷新令牌。认证失效交由预约执行器统一重新登录，并重做提交前准备；新令牌、新 id_token 与新验证码成套使用。认证失败最多触发一次准备重做，不重发已经发出的预约请求。
取消预约查询遇到认证失效时也会重新登录，后续检查与撤销使用同一套新凭据。
立即预约对验证码最多尝试 3 次，每次重新获取并校验，成功即停止重试，预约本身仍单次提交。

## 验证

```bash
python -m pytest tests/ -m 'not network'
python scripts/verify_rush_pipeline.py
ruff check src/ tests/
node --test tests/frontend/booking.test.cjs
```

生命周期测试使用临时数据库、假上游，覆盖并发冲突、终态竞争、异常收尾、取消期间成功、占位归属和旧库升级。
缓存测试验证跨账号共享公共资源但分别计算个人预约，以及请求取消后不会重复发起公共查询。
抢票脚本禁止真实 HTTP，8 个场景由 CI 单独执行。真实登录或预约脚本不属于离线回归。
